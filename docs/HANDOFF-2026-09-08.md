DGCA, MoCA, Gazette, DGFT, India Code and PIB material. The detailed clause map,

[drone regulation](research/drone-regulation.md).

| Finding or correction | Why it matters | Current disposition |
| --- | --- | --- |
| TC, UIN, RPC, airspace and import requirements are separate. | One exemption cannot be used as proof that every other gate has disappeared. | Explicitly separated in the research and planning docs. |
| Rule 42 provides conditional R&D exemptions for specified entities and controlled green-zone operations. | There may be a legitimate prototype path; neither a self-description as a startup nor the word pilot establishes eligibility. | Project eligibility and the actual test site remain open. |
| The non-TC suspension banner is not the whole instruction. | Brave exposed a public PDF describing a contact-and-document route for locally manufactured nano/model aircraft. | Instructions recovered; AEGIS approval is not established. See the exact declarations before considering an application. |
| The 2024 amendment changes identity/address evidence in D-2/D-3. | It belongs in the amendment chain but does not itself authorize autonomy or remove operating requirements. | English identification and operative amendments visually read in the original gazette through Brave. |
| Manufacturing a prototype is not identical to operating a certified aircraft. | Broad statements that every build must first obtain TC overstate the reviewed rules. | Older research claims receive an explicit applicability correction. |
| Nano/micro class does not establish blanket registration or commercial pilot exemptions. | Payload-inclusive weight and the purpose/conditions of the specific exemption matter. | Do not choose a mass target as an assumed legal workaround. |
| DGFT's prohibition contains authorization exceptions. | Neither freely importing a foreign security bundle nor declaring every such import impossible follows from the reviewed text. | Exact shipment classification, current policy and authorization remain open. |
| Autonomous UAS is a recognized category, not blanket unattended/BVLOS permission. | Technical flight capability and legal operating scope are different claims. | Residential unattended/BVLOS/night service remains unapproved. |
| Preflight restrictions can change, including temporary restrictions. | A signed privacy map or cached green-zone map alone cannot establish current launch eligibility. | Offline-dispatch design question recorded; runtime behavior unchanged. |

## 5. Proposed launch constraint, not an implemented decision

The preflight-airspace obligation exposes a question in the existing
offline-dispatch promise. The proposed resolution is to continue local sensing
and ground alerts while refusing a new aircraft launch when required current
permission evidence cannot be established. This must not be confused with
arbitrarily shutting down an aircraft that is already airborne; flight
contingencies and upstream failsafes remain a separate safety problem.

No legal cache lifetime, public API, approved operating envelope or launch-gate
implementation was invented. The proposal needs an explicit accepted design
resolution, and a new ADR if it changes an existing accepted contract. Future
simulation should exercise missing, expired and unavailable permission evidence
before any real arming integration. Those cases were not implemented or run here.
