# System Architecture

> Research note for [AEGIS](../../README.md). Compiled 2026-09-07 from a multi-agent
> web research sweep. Every claim below is sourced; confidence levels are the
> researcher's own and are preserved verbatim.

## Summary

Every serious platform in this space (FlytBase, Percepto AIM, DJI FlightHub 2 /
Cloud API, Auterion Suite) converges on the same three-tier shape: autonomy
onboard the aircraft, an orchestration + inference node at the site, and a cloud
that does fleet state, archive, analytics and multi-site coordination — FlytBase
names these explicitly as onboard / dock-level edge nodes / site-level edge
servers, and offers on-prem, sovereign private-cloud and hyperscaler
deployments. For India the decisive number is that measured glass-to-glass
WebRTC latency on the India→AWS Mumbai→India path over 4G is ~740 ms P50 / 1180
ms P95, while teleoperation research puts the usable ceiling at ~170–300 ms;
therefore remote manual piloting over public Indian cellular is not deliverable
and the cloud must never sit in the flight-critical loop — the cloud is
"supervise, abort, review", and manual takeover happens from an on-site/LAN
console (180–310 ms P50 measured on LAN). Build a Vehicle Abstraction Layer with
two adapters (DJI Cloud API over MQTT `thing/product/{sn}/{osd,state,services,events}`
+ KMZ/WPML missions; MAVLink 2 + MISSION_ITEM_INT for PX4/ArduPilot) so the
hardware decision stays reversible. The pragmatic 2026 stack for a 3–6 person
team: per-site Ubuntu edge node running Docker Compose with an MQTT broker,
MediaMTX (RTSP/RTMP ingest → WHEP egress, MIT-licensed, sub-500 ms), a local
inference worker and a NATS JetStream leaf node for store-and-forward; cloud in
AWS ap-south-1 running a FastAPI monolith, Postgres 17 + PostGIS (partitioned
telemetry — you do not need InfluxDB/QuestDB below ~10k points/sec), NATS
JetStream hub, S3 with lifecycle + Object Lock, and a React 19 + MapLibre GL +
deck.gl SPA. Licensing has moved against two obvious defaults: MinIO's community
repo was archived 25 Apr 2026 (source-only, AGPLv3) and EMQX ≥5.9 is BSL 1.1
with free production use limited to a single node — use Mosquitto/NanoMQ or
SeaweedFS/Garage instead. Security is dominated by CVE-2026-1579 (CVSS 9.8,
CISA ICSA-26-090-02, 31 Mar 2026): unsigned MAVLink lets anyone with link access
get a shell, so MAVLink 2 signing is mandatory on all non-USB links — but it
authenticates without encrypting and HEARTBEAT/RADIO_STATUS/ADSB_VEHICLE/COLLISION
bypass signing, so the link must additionally live inside WireGuard. Indian
mobile networks are CGNAT, so every connection must be outbound-initiated (edge
dials cloud) — no inbound ports, no static-IP SIM required. On alerting, budget
₹0.115/message for WhatsApp utility templates plus BSP fee plus 18% GST (₹0.8631
for marketing) and ₹0.12–0.22 per transactional SMS gated behind mandatory TRAI
DLT entity→header→template registration; app push (FCM) is free and should be
the primary channel. Finally, do not architect a dependency on
society-management apps: MyGate's developer portal is real but partner-gated and
scoped to entry/access/prepay (no resident-alert API), ADDA publishes a vendor
API, and NoBrokerHood exposes nothing public — ship a signed outbound webhook
and your own resident channel instead.

## Hard constraints

- MAVLink 2 message signing **MUST** be enabled on every non-USB link. Without
  it, anyone with link access can send SERIAL_CONTROL and get an interactive
  shell (CVE-2026-1579, CVSS 9.8, CISA ICSA-26-090-02, 31 Mar 2026). Signing
  authenticates but does NOT encrypt, and
  HEARTBEAT/RADIO_STATUS/ADSB_VEHICLE/COLLISION bypass signing — so a VPN layer
  is additionally mandatory, not optional.
- MAVLink signing keys **CANNOT** be recovered remotely. If the 32-byte key is
  lost on all GCS devices, recovery is physical only: pull the SD card and delete
  `/mavlink/mavlink-signing-key.bin`, or reflash via SWD/JTAG. Key escrow is
  therefore an operational requirement, and the SD slot and debug ports must be
  physically secured (SWD/JTAG bypasses all software security).
- MAVLink UDP/TCP ports **MUST NEVER** be exposed to the internet (explicit PX4
  hardening requirement and CISA mitigation).
- **No SMS can be sent** to an Indian number without completing TRAI DLT
  registration in order — Principal Entity → Header → Content Template — and
  every send must carry PE ID and Template ID or it fails carrier scrubbing.
  Transactional headers must be 6-character alpha; every template must contain
  the brand name; headers unused for 90 days are auto-deactivated;
  promotional-category SMS cannot reach DND numbers and is barred outside
  9 AM–9 PM (so security alerts must be registered transactional/service).
- WhatsApp messages sent outside an open 24-hour service window **MUST** use a
  pre-approved template — free-form alert text is impossible. Security alerts
  must be registered as Utility (₹0.115) not Marketing (₹0.8631). All India
  WhatsApp accounts must migrate to INR billing by 31 December 2026.
- Indian mobile carriers use CGNAT: the drone/edge node **cannot be reached
  inbound** from the internet. Every connection must be outbound-initiated (edge
  dials cloud) or go through a relay/VPN. This is a physical constraint of the
  network, not a preference.
- Residents' identifiable video is personal data under the DPDP Act 2023 as
  operationalised by the DPDP Rules 2025 (Gazette G.S.R. 846(E), notified
  13 Nov 2025; 18-month phased compliance, consent-manager provisions from
  13 Nov 2026). Consent notice, purpose limitation, enforced retention limits,
  erasure path and breach notification to the Data Protection Board are
  **required**.
- MinIO **cannot be used** as a supported dependency for new work: the community
  repository was archived 25 April 2026, is source-only (no binaries), AGPLv3,
  with the admin console removed from community in May 2025. Use S3, SeaweedFS
  (Apache 2.0) or Garage (AGPL-3.0).
- EMQX 5.9 and later are BSL 1.1: free production use is limited to a **SINGLE
  node**, and any cluster of more than one node requires a paid licence file.
  Only EMQX ≤5.8 remains Apache 2.0.
- AWS RDS **does not offer** the timescaledb extension — TimescaleDB means
  self-hosting Postgres on EC2 (or using Tiger Cloud). Plain partitioned Postgres
  on RDS is the zero-friction path.
- The DJI aircraft **never** connects directly to a third-party cloud; all Cloud
  API traffic is relayed via the RC or the Dock over DJI's proprietary AirLink.
  Any DJI integration must accept MQTT + HTTPS + one of RTMP/WHIP/GB28181/Agora
  as the only available interfaces.
- Remote manual piloting over public Indian cellular **cannot** meet the
  human-takeover latency threshold (measured 740 ms P50 / 1180 ms P95
  India→Mumbai→India on 4G, versus a ~170–300 ms usability ceiling). Manual
  control must be an on-site/LAN capability or use a dedicated RF C2 link.

## Findings

### Reference platform architectures

- **FlytBase publicly describes a three-tier edge model: onboard AI on the drone, dock-level edge nodes for fleet coordination/storage/mission analytics, and site-level edge servers aggregating multiple drones before forwarding to cloud; cloud does model training, historical storage, multi-site coordination and compliance.** — Claimed operational results from the same source: ~80% reduction in data transmission cost, up to 90% faster automated alert response, 3x reliability improvement. Hardware referenced: DJI Dock 2 (Matrice 3D) and Dock 3 (Matrice 4D). Specific wire protocols (MQTT/ROS) are not disclosed. [source](https://flytbase.com/blog/edge-computing-for-drone-data-processing)
- **FlytBase's platform is layered Hardware → Core (fleet orchestration) → Flinks (integrations) → AI Agents (visual detection on live drone video) → vertical solutions, and is offered in four deployment models including air-gapped on-prem and sovereign in-country private cloud.** — Deployment options listed: On-Premise (air-gapped, self-hosted), Private Cloud (sole-tenant, in-country, sovereign encryption), Hyperscaler (AWS/Azure), Fully Sovereign (jurisdiction-contained). Hardware-agnostic; supports DJI Matrice + Dock 2/Dock 3. Core features named: multi-feed video walls, real-time telemetry, automated collision avoidance/deconfliction, one-to-many pilot control. API docs at docs.flytbase.com (returns HTTP 403 to automated fetch). FlytBase is India-headquartered (Pune), which makes it a credible OEM/white-label alternative to building from scratch. [source](https://flytbase.com/platform)
- **Auterion Suite is a pure-cloud operations centre with no on-prem/edge deployment option advertised; all edge intelligence sits in AuterionOS on the vehicle, and AuterionOS uses mavlink-router to fan MAVLink between the flight controller, companion apps and payloads.** — Suite ingests telemetry, live video, flight logs and precision geo data during flight; offers OTA updates, predictive maintenance, pilot/asset management and 'API access for third-party and custom integrations'. AuterionOS is a hardened PX4 distribution running on Skynode. This is the opposite pole from FlytBase/Percepto: thin edge orchestration, thick cloud — a poor fit for Indian connectivity. [source](https://auterion.com/product/suite/)
- **Percepto AIM is cloud-based inspection/monitoring software; the public site does not document an on-prem or edge deployment model, SCADA/CMMS integration specifics, or component architecture.** — AIM automates data collection, upload and analysis; geospatially tags visual/sensor data; drones integrate directly with the AIM cloud. Percepto launched a next-generation 'inspection intelligence' platform for energy infrastructure in June/July 2026 combining Percepto Air drones, onboard autonomy, contextual AI and managed remote operations. [source](https://percepto.co/aim/)

### Vehicle, mission and airspace protocols

- **DJI's Cloud API (the protocol behind FlightHub 2, and what you implement to build your own FlightHub) is MQTT-based with a `thing/product/{gateway_sn}/...` topic tree, plus HTTPS for file/media upload to object storage.** — Topic categories observed: `thing/product/{sn}/osd` (telemetry), `/state`, `/services` (cloud→device commands), `/services_reply`, `/events`, `/requests`, `/property/set`. Media files transfer to object storage (AWS S3 or MinIO). Two integration paths exist: Pilot-to-Cloud (via RC) and Dock-to-Cloud. A third-party cloud must pre-deploy its own MQTT broker and streaming media server. Note: the dji-sdk/DJI-Cloud-API-Demo reference implementation (Java/Maven) has been unmaintained since 10 Apr 2025 and is explicitly 'not a production-level solution'. [source](https://deepwiki.com/dji-sdk/Cloud-API-Doc)
- **DJI Dock supports four livestream protocols — Agora, RTMP, GB28181 and WebRTC/WHIP — controlled by MQTT service methods `live_start_push` / `live_stop_push` / `live_set_quality` / `live_lens_change`. The aircraft never connects directly to your cloud; everything is relayed through the RC or the Dock over DJI's proprietary AirLink.** — WHIP (WebRTC-HTTP Ingestion Protocol) is the standardised WebRTC ingest path and is the one to use for low latency; Agora is a paid third-party CDN dependency; GB28181 is a Chinese public-security standard you should ignore. Quality enum values and bitrate/resolution mappings are in the Server API chapter, not this page. Practical implication: your streaming server must accept WHIP ingest — MediaMTX does. [source](https://github.com/dji-sdk/Cloud-API-Doc/blob/master/docs/en/30.feature-set/20.dock-feature-set/30.dock-livestream.md)
- **DJI missions are represented as a KMZ archive containing `wpmz/template.kml` and `wpmz/waylines.wpml`, using KML extended with a `wpml:` namespace; gimbal actions are first-class (e.g. gimbalEvenlyRotate triggered betweenAdjacentPoints, gimbal pitch/roll/yaw with mount-position index for multi-gimbal aircraft).** — template.kml carries mission structure/templates; waylines.wpml carries the executable waypoint/action sequence. Wayline missions are uploaded, then executed/paused/resumed/monitored over the Cloud API. This is the concrete target format your canonical route model must compile to if you use DJI Dock. [source](https://developer.dji.com/doc/cloud-api-tutorial/en/api-reference/dji-wpml/common-element.html)
- **mavlink2rest (Rust, mavlink/mavlink2rest) exposes MAVLink as REST + WebSocket — GET/POST `/v1/mavlink` for hierarchical JSON message access, GET `/v1/ws/mavlink` with regex subject filtering (e.g. `?filter=RC_.*`), `/v1/helper/mavlink?name=MESSAGE_NAME`, Swagger at `/docs` — supporting MAVLink v1 and v2 with the ardupilotmega dialect.** — Benchmarked at ~725 requests/sec on a Raspberry Pi 3, with CPU scaling linearly in concurrent connections and message rate. This is the right glue if you go the PX4/ArduPilot route: it lets your Python site-agent read/write MAVLink over HTTP/WS instead of linking a MAVLink library, at the cost of an extra hop. mavlink-router (used by AuterionOS) handles the UART↔UDP↔TCP fan-out below it. [source](https://github.com/mavlink/mavlink2rest)
- **ASTM F3548-21 strategic deconfliction (operational intents as 4D volumes exchanged via a Discovery and Synchronization Service) has a free Apache-2.0 reference implementation in Go — the InterUSS DSS — which also implements ASTM F3411-19/-22 Remote ID and EU 2021/664.** — F3548-21 defines the Strategic Coordination role: Strategic Conflict Detection plus Aggregated Operational Intent Conformance Monitoring; volumes are sized from UAS performance to hit a target level of safety. Strategic deconfliction is credited with reducing midair collision probability by 2–3 orders of magnitude. Repo: github.com/interuss/dss, Docker-deployable. For a single society with 1–3 drones this is heavy machinery — but it is the right pattern to imitate (4D volume reservations), and the right thing to adopt if India's UTM framework later mandates USS interoperability. [source](https://github.com/interuss/dss)

### Indian network reality and the latency budget

- **Measured MediaMTX WHIP/WHEP glass-to-glass latency across four production deployments (Q3 2025–Q1 2026): India→AWS Mumbai→India over 4G is 740 ms P50 / 1180 ms P95; on-prem LAN is 310 ms P50 / 480 ms P95; edge-AI LAN loopback on an RK3568 is 180 ms P50 / 240 ms P95.** — MediaMTX-internal latency is consistently only 30–80 ms; almost all of the remainder is network RTT plus publisher-side encoder pipeline. Hardware encoders (NVENC, RK3568 V4L2 H.264, Apple VideoToolbox) shave 80–150 ms versus software x264. A poorly placed TURN relay adds 200+ ms — co-locate TURN with the media server. Budget 4–6 weeks of tuning, not 1 week. [source](https://www.adaptnxt.com/blogs/mediamtx-whip-whep-latency-benchmarks-4-deployments)
- **Teleoperation research puts the usable human-takeover latency ceiling at roughly 170 ms (good), 300 ms (difficult) and 400 ms (unworkable); operator trust degrades above ~150 ms and precise control becomes unreliable above ~250 ms.** — Most teleop platforms sit at 150–400 ms glass-to-glass. Combined with the measured 740 ms P50 India-cloud-4G figure, this means cloud-mediated manual flight over Indian public cellular fails the threshold by roughly 2–4x. Design consequence: manual takeover must be an on-site/LAN capability; the cloud console gets 'pause / hold / RTL / land / terminate' buttons, not sticks. [source](https://arxiv.org/pdf/2503.14186) *(likely)*
- **India's 5G median multi-server latency is 51.6 ms and median upload is 15.75 Mbps (only 7.53% of throughput allocated to uplink); median cloud latency from India is 108 ms to Azure, 114 ms to AWS, 115 ms to Google Cloud, 158 ms to OCI.** — India is one of only four markets (with South Korea, US, Spain) above the sub-50 ms threshold; uplink is below the 20 Mbps benchmark. Source is an Ookla report reported July 2026. Design consequence: one 1080p uplink at 2–3 Mbps per drone is the realistic budget; do not plan on pushing 4K or multiple simultaneous streams from a site over cellular, and expect ~110 ms one-way-ish RTT floor to any hyperscaler even on good links. [source](https://www.business-standard.com/technology/artificial-intelligence/india-s-5g-speed-is-good-but-lags-on-ai-applications-126070700647_1.html) *(likely)*
- **Tailscale/WireGuard beats ZeroTier for this use case: on Linux kernel ≥5.6 Tailscale uses kernel WireGuard (1+ Gbps, sub-ms added latency, ~80% direct P2P success), while ZeroTier is always userspace (~200–400 Mbps under full CPU, ~70% P2P) and its L2 encapsulation adds overhead you do not need.** — Indian carriers hand out CGNAT-private addresses to both drone/edge and GCS, so neither can reach the other directly — a VPN or relay is mandatory for MAVLink over LTE. Recommended split: a plain self-hosted WireGuard tunnel edge→cloud VPC as the deterministic data path (no third-party dependency, no per-device SaaS cost), plus Tailscale for human/ops SSH access to edge nodes. [source](https://onidel.com/blog/wireguard-vs-tailscale-vps-2025) *(likely)*

### Streaming, messaging, storage and map components

- **MediaMTX is a single Go binary that ingests and serves RTSP, RTMP, SRT, WebRTC (WHIP/WHEP) and HLS simultaneously, uses under 20 MB RAM, supports on-demand source pulling and built-in recording/playback, and delivers sub-500 ms WebRTC versus 2–8 s for HLS.** — Cross-protocol bridging means one RTSP camera/drone feed is instantly available as HLS, WebRTC, RTMP and SRT. On-demand pulling means the camera is only contacted when a viewer connects — important for saving Indian uplink bandwidth on idle sites. MIT-licensed, formerly rtsp-simple-server. [source](https://mediamtx.net/)
- **NATS JetStream leaf nodes implement bidirectional store-and-forward natively: a leaf keeps serving its local clients and committing writes while disconnected from the hub, and stream mirrors/sources flush buffered messages in both directions when the link returns — even across multi-day outages.** — Pattern: use a mirror of a hub stream to receive commands offline-tolerantly at the edge; use a source on the hub to aggregate streams from N leaf sites. Reconciliation is via explicit mirrors/sources across JetStream domains, not a shared cluster. NATS server is a ~20 MB single binary using 10–50 MB base RAM (100–500 MB under load), ~11–12M msgs/sec core and ~1M msgs/sec with JetStream durability, sub-millisecond tail latencies, Apache 2.0. Known caveat: GitHub issues report leaf-to-hub sync failures after reconnection in some configurations (e.g. nats-server #6468 on v2.10.24, #7530) — test your reconnect path explicitly. [source](https://docs.nats.io/running-a-nats-service/configuration/leafnodes/jetstream_leafnodes)
- **For a small team, NATS JetStream beats Kafka and Redis Streams on operational cost while meeting the throughput need; Redis Streams is adequate below ~10K msg/s but has no edge topology, and Kafka only earns its complexity when multiple independent teams consume the same data differently.** — NATS: ~20 MB binary, 10–50 MB base RAM, sub-ms tail latency, native leaf-node/edge topology. Kafka 4.0's KRaft migration reduced operational friction, weakening the 'too complex' argument, but it still offers nothing NATS lacks at this scale. NATS's documented scaling caveat: subject-naming conventions and bridge CPU overhead become painful as fleets grow past ~50,000 devices with many consuming teams — not a concern for hundreds of societies. [source](https://www.javacodegeeks.com/2026/03/nats-vs-kafka-vs-redis-streams-for-java-microservices-when-simpler-actually-wins.html) *(likely)*
- **TimescaleDB is now branded Tiger Data / Tiger Cloud (Apache 2.0 core, TSL for community features) with 90%+ columnstore compression; QuestDB (Apache 2.0) is 6–13x faster than TimescaleDB on TSBS ingest and sustains 7.1–8.6M rows/sec, and 12–36x faster than InfluxDB 3 Core.** — QuestDB claims 16–20x faster complex queries than TimescaleDB and 43–418x vs InfluxDB 3 Core (vendor-published benchmarks, treat directionally). The decision rule that actually matters here: a 100-site fleet at 2 drones/site × 5 Hz flying ~72 min/day generates roughly 4–5M telemetry rows/day — three orders of magnitude below where a specialised TSDB pays for itself. Use Postgres + PostGIS with declarative time partitioning (or the TimescaleDB extension if self-hosting on EC2 — note AWS RDS does not offer the timescaledb extension), and only migrate to QuestDB above ~10k points/sec sustained. [source](https://www.tigerdata.com/learn/the-best-time-series-databases-compared) *(likely)*
- **For self-hosted WebRTC in 2026: LiveKit is an Apache-2.0 Go SFU built on Pion with full SDKs (50–150 ms), mediasoup is a C++/Node engine with the deepest control (40–100 ms, ~500–800 concurrent video participants per node), and Pion is a library, not an SFU. Self-hosting only beats managed above roughly $30k/month of managed spend.** — For a drone dashboard the viewer count per stream is tiny (1–5 operators), so an SFU's fan-out advantage barely applies — MediaMTX's built-in WebRTC server is sufficient and far simpler. Reach for LiveKit only if you add many-to-many operator conferencing, recording/egress orchestration, or AI agents on the media path. [source](https://www.forasoft.com/learn/video-streaming/articles-streaming/sfu-comparison-mediasoup-janus-livekit-jitsi-pion) *(likely)*
- **MapLibre GL JS terrain is 2.5D raster-DEM with no globe curvature and degrades at very small scales; CesiumJS is the correct choice only if you ingest drone-derived 3D Tiles, photogrammetry meshes or point clouds (quantized-mesh terrain).** — A residential society is a few hundred metres across — MapLibre's extruded building footprints plus a 2.5D DEM is entirely sufficient and vastly lighter. react-map-gl provides idiomatic React bindings. Adopt CesiumJS as a second, lazily-loaded view only when/if you start producing 3D reconstructions of the site. [source](https://maplibre.org/projects/gl-js/) *(likely)*

### Security and licensing landmines

- **CVE-2026-1579 (CVSS 9.8 CRITICAL, CISA advisory ICSA-26-090-02, published 31 March 2026) affects PX4 Autopilot: with MAVLink message signing disabled, an attacker with link access can send SERIAL_CONTROL and obtain interactive shell access without any authentication.** — Mitigations: enable MAVLink 2.0 message signing on all non-USB links; network-isolate behind firewalls; use VPNs for remote connections. Affected build named: PX4 Autopilot v1.16.0_SITL_latest_stable. Sectors flagged: Transportation Systems, Emergency Services, Defense Industrial Base. [source](https://www.cisa.gov/news-events/ics-advisories/icsa-26-090-02)
- **MAVLink message signing provides authentication and integrity but NOT encryption (messages remain plaintext), and HEARTBEAT, RADIO_STATUS, ADSB_VEHICLE and COLLISION are allowlisted to bypass signing — leaving those specific messages spoofable. There is no automatic key rotation.** — Setup: provision a 32-byte secret via SETUP_SIGNING over a trusted link (USB recommended); the same key goes to every GCS and companion computer; key file lives at `/mavlink/mavlink-signing-key.bin` on the SD card. If the key is lost on all GCS devices, recovery is physical only — pull the SD card and delete the key file, or reflash via SWD/JTAG. Additional hardening: secure the SD slot, protect SWD/JTAG debug ports (they bypass all software security), control USB access, never expose MAVLink UDP/TCP to untrusted networks, audit companion-computer interface bindings. [source](https://docs.px4.io/main/en/mavlink/security_hardening)
- **MinIO's open-source repository was archived on 25 April 2026 with the notice 'THIS REPOSITORY IS NO LONGER MAINTAINED'; the community edition is now source-only (no pre-compiled binaries) under AGPLv3, and the admin console/UI was stripped from community in May 2025.** — README states 'All usage of MinIO in your application stack requires validation against AGPLv3 obligations' and 'Production environments using compiled-from-source MinIO binaries do so at their own risk.' Users are pushed to AIStor Free (standalone) or AIStor Enterprise. Policy management, site replication and lifecycle management moved to the commercial edition. Practical alternatives: SeaweedFS (Apache 2.0, most mature, handles mixed small/large file sizes well) or Garage (AGPL-3.0, Rust, the only real option for geo-distributed multi-site). [source](https://github.com/minio/minio)
- **EMQX 5.9.0 and all later releases moved from Apache 2.0 to Business Source License 1.1 (announced 7 May 2025). Free production use is limited to a SINGLE node; running a cluster of more than one node requires a paid license file.** — BSL includes an Additional Use Grant for a single production node; accredited academic institutions and registered non-profits get unrestricted non-commercial production use. Each version reverts to Apache 2.0 after four years. EMQX ≤5.8 stays Apache 2.0 forever. Consequence for this project: at the edge use Mosquitto (EPL/EDL) or NanoMQ; do not plan an EMQX cluster in the cloud without budgeting a licence. [source](https://www.emqx.com/en/news/emqx-adopts-business-source-license)

### Alert delivery, society-app integration, storage cost and compliance

- **WhatsApp Business Platform India rate card (INR billing, effective 1 Jan 2026): Marketing ₹0.8631/message, Utility ~₹0.115, Authentication ~₹0.115, Service (free-form reply inside the 24-hour window) free. 18% GST applies on both Meta's charges and the BSP platform fee.** — Marketing rose ~10% from ₹0.7846. Utility inside an open 24-hour service window is currently free; utility outside the window and all authentication messages are charged. Authentication-International (OTP to Indian users from a non-Indian WABA) is ~$0.035 — a ~20x markup, so register an Indian WABA. Meta requires all India accounts to migrate to INR billing by 31 Dec 2026. Indian BSPs typically add 10–30% markup. Volume discounts up to 30% off list on utility/authentication. Classification is OIDAR; reverse charge applies for GST-registered Indian businesses. You are charged only on delivery, and all non-template messages inside the service window are free. [source](https://whautomate.com/whatsapp-business-api-pricing-india)
- **Sending any SMS to Indian numbers requires TRAI DLT registration in strict order — Principal Entity → Header (sender ID) → Content Template — and every API request must carry the PE ID and Template ID or the message fails DLT scrubbing.** — Transactional/service SMS needs a 6-character alpha sender ID. Since May 2025 carriers auto-append a category suffix during scrubbing: -T transactional, -S service, -P promotional, -G government. Every template must contain the business's brand/trademark name in the message body. Headers unused for 90 days are automatically deactivated. One-time DLT registration fee ~₹5,900 + GST per operator. Transactional/OTP SMS reaches DND numbers 24/7; promotional is restricted to non-DND and 9 AM–9 PM only — security alerts must be registered as transactional/service, never promotional. Street pricing 2026: ₹0.12–₹0.22 per transactional SMS (MetaReach ₹0.12, MSG91 ₹0.14–0.15, Gupshup ₹0.17, Exotel ₹0.18, Kaleyra ₹0.18). [source](https://www.messagecentral.com/sms-guideline/india) *(likely)*
- **MyGate operates a real developer portal (tech.mygate.in) with four documented API families — Express Entry (Delivery EAR, Partner Match, Geofence), Hardware Access Control, Address widget, and Utility Prepay — with partner callbacks, but access is partner-gated and none of it is a general 'push a security alert to residents' API.** — Integration requires offline exchange of sandbox credentials, a registered Callback URL plus callback authentication, logo and PoC details; MyGate's Partner Engineering Team supports it and integration is quoted at 'not more than a week' before a GO-LIVE date. A 'Partner Callback Event' API delivers status notifications back to the partner. Contact is a protected email on the portal. [source](https://tech.mygate.in/expressentry/)

Do not put a society app in the alert delivery critical path — own your resident channel (your app's FCM push + WhatsApp). [source](https://api.adda.io/docs/vendor/) *(likely)*
